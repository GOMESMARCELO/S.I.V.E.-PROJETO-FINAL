S.I.V.E. — HTML, CSS, JavaScript, JSON, Node.js e MySQL

PASSO A PASSO
1. Abra o MySQL Workbench conectado ao seu servidor local e execute, nessa ordem:
     a) database/criar-usuario.sql   (cria um usuário chamado "sive", senha "sive123", só para este projeto)
     b) database/sive.sql            (cria o banco "sive" com as tabelas e os dados)
2. O config.json já vem pronto com usuário "sive" e senha "sive123" — não precisa mexer,
   a menos que você prefira usar outro usuário do seu MySQL (ex.: root).
3. No terminal, dentro desta pasta:
     npm install
     npm start
4. Abra no navegador: http://localhost:3000

BACKUP (FAÇA!)
O servidor faz sozinho um backup por dia, CRIPTOGRAFADO (banco inteiro + pasta uploads/), na pasta backups/.
Ficam os 14 mais recentes. Para mudar a pasta ou a quantidade, no config.json:
    "backup": { "pasta": "D:\backups-sive", "manter": 30 }
Para fazer um na hora:  npm run backup
Para restaurar:
    node backup.js --decifrar backups/<pasta>/sive.sql.enc      (gera o sive.sql)
    mysql -u root -p sive < backups/<pasta>/sive.sql           (e copie a pasta uploads/ de volta)
    depois APAGUE o sive.sql gerado (ele tem os dados em texto aberto).
IMPORTANTE: guarde uma cópia do config.json em OUTRO lugar seguro, separada dos backups.
Sem ele, os backups, os documentos e as assinaturas não abrem; com ele junto dos backups, quem pegar os dois lê tudo.
O projeto está dentro do OneDrive: o ideal é movê-lo para uma pasta fora da nuvem (ex.: C:SIVE).
Os logs de atividade com mais de 2 anos são apagados sozinhos (config.json: "retencao": { "logs_anos": 2 }).

SEGURANÇA DO LOGIN
- Senhas: pelo menos 8 caracteres, com letras e números. Quem entrar com senha fraca (ex.: 123456)
  é obrigado a criar uma nova antes de usar o sistema.
- Gestão: no primeiro login, configura a verificação em duas etapas (aplicativo autenticador no celular:
  Google Authenticator, Microsoft Authenticator...). Perdeu o celular? Outra pessoa da gestão usa
  "Zerar 2 etapas" em Usuários.
- "Sair" encerra o login em todos os aparelhos. Trocar a senha encerra os outros aparelhos.
- Só para DEMONSTRAÇÃO (nunca com dados reais), dá para desligar as duas regras no config.json:
    "seguranca": { ..., "exigir_senha_forte": false, "exigir_2fa_gestao": false }
- Publicação na internet: use HTTPS. Ou o sistema sobe direto em HTTPS com
    "https": { "certificado": "caminho/cert.pem", "chave": "caminho/chave.pem" }
  ou, atrás de um Nginx com HTTPS, use "seguranca": { ..., "atras_de_proxy": true }.

BANCO JÁ EXISTENTE (atualização)
Se o seu banco foi criado com uma versão anterior, rode database/migracao-atualizacao.sql
(depois de um backup). Ele não apaga dados.
Se o seu banco JÁ ESTAVA atualizado até 31/10/2026, rode só database/migracao-2026-11-02.sql
(duas colunas novas: prazo das autorizações e avisos vistos). Também não apaga dados.
XAMPP (MariaDB): o sive.sql agora roda nele também.

LOGIN
O sistema pede login. Três tipos de usuário, já cadastrados no banco (senhas de DEMONSTRAÇÃO: no primeiro login
elas são consideradas fracas e o sistema pede uma senha nova; a gestão também configura as duas etapas):
  Administração -> usuário: mariana   senha: 123456   (vê tudo)
  Responsável   -> usuário: anapaula  senha: 123456   (vê só os dados do próprio filho)
  Professor(a)  -> usuário: patricia  senha: 123456   (vê só a própria turma)
  Outros (senha 123456): claudia (mãe da Ana Clara), marcos (pai da Beatriz),
  roberto (professor há 75 dias sem acessar) e fernanda (professora há 53 dias sem acessar).

A administração cadastra novos usuários pela própria tela do sistema
(menu "Usuários"). A senha é gerada automaticamente (6 dígitos) e marcada
como provisória — no primeiro login, a pessoa é obrigada a trocar a senha
antes de continuar. Qualquer usuário também pode trocar a senha quando
quiser, pelo botão 🔑 ao lado do nome, no menu.

Toda ação importante (login, cadastro de aluno, cadastro de usuário, troca
de senha, aprovações etc.) fica registrada no menu "Logs", visível só para
a administração.

FREQUÊNCIA E BUSCA ATIVA (Fase 2)
- Professor(a): em "Minha Turma" faz a chamada de hoje (Presente/Ausente) e clica em
  "Salvar chamada de hoje". Só enxerga os alunos da própria turma.
- Gestão: "Frequência" mostra a presença de qualquer dia (escolha a data) e o histórico
  de cada aluno; os quadros da Central do Dia (Total, Presentes, Ausentes) vêm do banco.
  Se hoje for fim de semana, o quadro mostra o último dia com chamada registrada.
- Busca Ativa: o sistema conta as faltas sozinho e abre o caso quando o aluno chega a
  5 faltas nos últimos 30 dias. A gestão anota o acompanhamento e encerra o caso.
  Para mudar a regra, edite BUSCA_ATIVA no começo do server.js (faltas e dias).
- Relatório Mensal: escolha o mês; dá para imprimir / salvar em PDF e baixar em CSV (Excel).
- Responsável: vê a frequência dos últimos 30 dias e se o filho está presente ou ausente hoje.

IMPORTANTE AO ATUALIZAR DA FASE 1 PARA A FASE 2: rode o database/sive.sql de novo
(ele cria as tabelas de Busca Ativa e gera presenças de exemplo dos últimos 35 dias úteis,
sempre contando a partir da data de hoje). Isso apaga os dados antigos do banco "sive".


GESTÃO, FICHA DO ALUNO E AUTORIZAÇÕES DIGITAIS (Fase 3)
- Central do Dia (gestão): a tabela de alunos mostra comunicados (lidos/novos), autorizações
  (em dia/pendentes), pendências e ações/advertências. Dá para buscar, filtrar, ordenar clicando
  nos títulos e abrir a "ficha" de cada aluno.
- Ficha do aluno (abas): Comunicados, Autorizações, Documentos, Pendências e Ocorrências.
  Gestão vê qualquer aluno; professor vê só a própria turma; responsável vê só o próprio filho.
- Documentos: PDF, PNG, JPG, DOC ou DOCX (até 5 MB). Ficam na pasta uploads/ (não é pública).
  Se o documento atende a uma pendência do tipo "Documento", ela é resolvida junto.
- Comunicados: gestão publica para a escola toda ou uma turma; professor publica para a própria
  turma. O responsável marca como lido e a gestão acompanha quantos leram.
- Autorizações digitais: a gestão envia (para uma turma ou todos) e o responsável assina com nome
  completo + senha. O sistema grava quem assinou, quando e um código de verificação, e gera um
  comprovante para imprimir.

IMPORTANTE AO ATUALIZAR DA FASE 2 PARA A FASE 3: rode o database/sive.sql de novo (apaga os dados
antigos do banco "sive"). Não precisa rodar npm install de novo: nenhuma biblioteca nova foi adicionada.

SEGURANÇA: o servidor agora só entrega as pastas css/, js/ e assets/ e o index.html. Antes, o
config.json (com a senha do banco) e o server.js podiam ser baixados pelo navegador. A pasta
uploads/ também não é pública e não vai para o Git.
